# Внешняя настройка и запуск

Проект включает PostgreSQL и Redis в Docker Compose. Покупать отдельную БД для начала не требуется. Все пункты ниже выполняются в ваших аккаунтах или на VPS. Не отправляйте токены в чат и не коммитьте их в Git.

## 1. Репозиторий и версии

1. Создайте **приватный** репозиторий GitHub, например `researcher`. Полученный архив распакуйте, затем из корня проекта выполните `git init`, `git add .`, `git commit -m "Initial Researcher MVP"` и добавьте remote своего репозитория. Отправьте основную ветку командой `git push -u origin main` (при необходимости сначала `git branch -M main`).
2. Включите защиту `main`: pull request перед merge и обязательную проверку `CI / test`. Настройте Dependabot или Renovate для обновления зависимостей и Docker-образов.
3. Миграции схемы находятся в `alembic/versions`. При изменении моделей добавляйте новую миграцию через Alembic, коммитьте её вместе с кодом и применяйте перед обновлением контейнеров. Не редактируйте уже применённую миграцию.
4. CI в `.github/workflows/ci.yml` запускается на push и pull request. Для него не нужны продакшен-секреты. Деплой через `.github/workflows/deploy.yml` запускается вручную из GitHub Actions и требует настройки окружения `production`. Добавьте approval rule для окружения, если репозиторий и тариф её поддерживают.

## 2. Ключи внешних платформ

1. Создайте отдельный ключ OpenAI API и установите лимиты расходов в кабинете API. Подписка ChatGPT не предоставляет этому проекту API-бюджет. Запишите `OPENAI_API_KEY` в `.env` только на сервере.
2. Создайте Telegram-бота через BotFather. Создайте **частный канал**, добавьте бота администратором с правом публиковать сообщения. Укажите `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL_ID` (числовой ID вида `-100...`) и `TELEGRAM_OWNER_ID` в `.env`. ID канала можно узнать через временный служебный запрос Bot API `getUpdates` после публикации сообщения ботом в канале; если webhook или polling уже запущен, остановите его на время проверки.
3. Создайте Reddit API-приложение и получите доступ, разрешённый для вашего сценария. Если доступа нет, оставьте Reddit вне `sources.json`. Не используйте авторизацию личного аккаунта обходными способами.
4. Для YouTube создайте Google Cloud Project, включите YouTube Data API v3, выпустите API-ключ и ограничьте его этим API и IP сервера, если применимо. Укажите `YOUTUBE_API_KEY`.
5. RSS и Stack Exchange начнут работать без пользовательских ключей в пределах доступных квот. Для App Store RSS проверьте доступность ленты выбранного приложения и страны.

## 3. VPS, Docker и БД

1. Арендуйте VPS с Linux и минимум 2 vCPU/4 GB RAM/40 GB SSD. Настройте SSH-ключ, обновления безопасности и firewall. Откройте только SSH; API привязан к `127.0.0.1:8000`, PostgreSQL и Redis наружу не публикуются.
2. Установите Docker Engine и Docker Compose v2. Разверните приватный репозиторий на VPS в отдельной директории.
3. Создайте `.env` из `.env.example`. Замените `POSTGRES_PASSWORD` и тот же пароль в `DATABASE_URL`. Для пароля с `@`, `:`, `/`, `%` используйте URL-кодирование в `DATABASE_URL`. Заполните API и Telegram-ключи, установите `chmod 600 .env`.
4. `docker compose up -d --build`. Контейнер `db` **сам создаст** базу `researcher` и пользователя `researcher` при первом запуске. Контейнер `migrate` применит миграции и создаст таблицы и расширение pgvector. Данные лежат в именованном томе `db_data` и переживают пересборку контейнеров.
5. Создайте `sources.json` из `sources.example.json`, удалите заглушки и ненужные источники. Загрузите файл и выполните seed командами в README. Команда `docker compose exec worker python scripts/seed.py /tmp/sources.json` обновит источники по имени.
6. Проверьте `docker compose ps`, `curl http://127.0.0.1:8000/health`, `docker compose logs --tail=100 worker beat bot` и `/status` в личном чате бота. Запустите `/collect`; после появления подходящих кластеров выполните `/publish`.
7. При необходимости внешнего API позже поставьте Caddy как reverse proxy с доменом и TLS; текущий Telegram-бот работает через long polling и не требует домена.
8. Когда ручной запуск проверен, создайте отдельный SSH-ключ для GitHub Actions с доступом только к пользователю деплоя. В secrets окружения `production` добавьте `SSH_PRIVATE_KEY`, `SSH_KNOWN_HOSTS` (отпечаток хоста проверьте отдельно), `SSH_HOST`, `SSH_USER` и `DEPLOY_PATH` (путь к проекту на VPS). Убедитесь, что сервер может делать `git pull` из приватного репозитория. Запускайте workflow `Deploy` вручную только после успешного `CI`.

## 4. Резервное копирование и обновление

1. Запланируйте `scripts/backup.sh` ежедневно через cron. Отправляйте дампы в отдельное хранилище (S3 либо другой сервер), а не храните единственную копию на VPS. Храните секреты и дампы вне Git.
2. Один раз восстановите дамп на отдельной тестовой базе: `pg_restore -U researcher -d researcher_test --clean --if-exists backup.dump`. Для этого сначала создайте `researcher_test`. Зафиксируйте дату и результат проверки.
3. Для обновления используйте ручной workflow `Deploy` либо на сервере `git pull --ff-only origin main` и `docker compose up -d --build`. `migrate` применяет новые миграции перед запуском API и воркера. Перед несовместимой миграцией сделайте дамп и проверьте план отката.
4. Проверяйте ошибки в логах после обновления, квоты источников и счёт API-провайдера. Добавьте внешний мониторинг доступности VPS и отдельное оповещение о падении `worker` и `beat`.

## Ожидаемые затраты

- VPS: приблизительно $12–25/мес., зависит от провайдера и региона.
- Отдельная копия БД: примерно $3–10/мес. при небольшом объёме.
- AI API: задайте стартовый лимит $20/мес.; реальная сумма зависит от числа обработанных текстов и модели.
- Telegram, PostgreSQL, Redis, Docker, GitHub CI в пределах бесплатных квот не требуют отдельного платежа.
- Reddit или платные поставщики отзывов могут иметь собственные условия и тарифы; в расчёт минимального MVP не включены.
